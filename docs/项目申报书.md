### 项目简介
mtuck 是一个用 MoonBit 编写、原生编译的跨平台终端剪贴板历史管理器。它把系统剪贴板从一个只有一格、下次复制就覆盖的临时缓冲区，变成一条可回溯、可搜索、可固定、可脚本化的时间线：常驻监听记录每一次复制，随时列出、查看、并写回剪贴板，也负责固定、删除与清理历史规模。项目名称取自 MoonBit 与 tuck（把东西塞进兜里收起来），复制过的片段随手收好，需要时再拿出来。

与常见的 Electron / Tauri 剪贴板管理器相比，mtuck 是原生编译的单二进制 CLI：不需要 Electron、Node 或 JVM 这类语言运行时，启动即用，不占后台 GUI 资源。与 Windows 剪贴板历史、macOS 上的 Paste / Maccy、Linux 上的 clipse / CopyQ 等同类工具相比，本项目做了以下重新设计：以终端 CLI 加单二进制为交付形态，不做常驻 GUI，记录与写回依赖剪贴板后端，而历史的检索与管理只依赖纯文本文件，因此可在远程终端与容器内消费同一份历史；历史文件刻意选择纯文本格式而非数据库或二进制，保证可读、可 diff、可手工修复；把密钥识别与默认打码作为核心默认行为而不是可选项；按依赖方向严格分层，纯逻辑、事件源与 I/O 相互独立，使核心逻辑可以在任意后端上快速测试。

- **交付形态**：MoonBit 原生编译，单二进制，无 Electron / Node / JVM 等语言运行时，无 GUI；
- **依赖边界**：剪贴板读写全部在本仓库内实现，不依赖任何第三方剪贴板包；**Windows** 与 **macOS** 无需额外依赖，**Linux 需预装图形服务器剪贴板客户端**；
- **可用性边界**：Linux 上需要可连接的图形服务器（X11 DISPLAY 或 Wayland WAYLAND_DISPLAY），纯 SSH、无图形服务器的容器里不可用；Windows 与 macOS 无此限制；
- **技术路线**：以 CLI 形式分发，Windows / macOS 通过 FFI 直接调用 Win32 / AppKit 系统原生 API，Linux 经 C stub 调用系统剪贴板命令行工具；

### 核心功能范围
- **常驻记录**：后台按可配置间隔监听剪贴板，内容变化持久化；启动前先探测剪贴板后端是否可用，不可用直接给出报错而不是静默失败；
- **历史模型**：最新一条始终在最前，编号即位置；重复内容自动合并并排序到最前；固定条目永不淘汰，超出容量时淘汰最旧的未固定条目；
- **内容类型判定与保密**：识别私钥块、常见密钥/令牌关键词、JWT 与带账号密码的连接串等；密钥类内容在列表、详情和结构化输出中默认打码，显式参数才显示原文；
- **命令行检索**：支持条数截断、只看固定条目、子串过滤；条目操作使用统一编号语法，支持最新一条、多选与区间批量处理；
- **脚本友好**：列表与统计支持结构化输出，便于与其他命令行工具组合；退出码区分成功、运行期错误与用法错误；
- **健壮持久化**：采用纯文本格式存储，存储层不需要数据库或第三方序列化库、可读可 diff、可手工修复；坏行跳过不影响其余数据；
- **可测试架构**：历史模型是无 I/O 的纯逻辑，测试不依赖真实系统剪贴板；检查、格式与测试流程接入持续集成。

### 预期验收产物
- 原生编译产出的单二进制可执行程序，优先保证 Windows 可用，在 macOS、Linux（Wayland / X11）通过 CI 测试确保质量；
- 可复用的 MoonBit 库：历史模型、类型判定与打码、存储编解码、剪贴板轮询器，可被其他 MoonBit 项目引入；
- 自动化测试覆盖去重合并、固定与淘汰、类型判定与打码、存储编解码、轮询变更检测等核心路径，并在持续集成中运行；
- README 文档，涵盖安装、用法、工作原理、项目结构与已知限制，并逐平台列出剪贴板依赖与可用命令范围；

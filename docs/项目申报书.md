### 项目简介
mtuck 是一个用 MoonBit 编写、原生编译的跨平台终端剪贴板历史管理器。它把系统剪贴板从一个只有一格、下次复制就覆盖的临时缓冲区，变成一条可回溯、可搜索、可固定、可脚本化的时间线：常驻监听记录每一次复制，随时列出、查看、并写回剪贴板，也负责固定、删除与清理历史规模。项目名称取自 MoonBit 与 tuck（把东西塞进兜里收起来），复制过的片段随手收好，需要时再拿出来。

项目面向终端重度用户与开发者：复制过的命令、URL、代码片段都能按编号或搜索找回，并直接组合进脚本；也面向 MoonBit 生态的使用者：这是少数以真正交付给普通用户的跨平台桌面工具为目标、而非库或算法移植的 MoonBit 项目，展示了 MoonBit 在系统编程、FFI、异步任务和 CLI 工程化方面的能力边界；还面向关注隐私的工具作者：剪贴板是密钥泄露最容易被忽视的通道，mtuck 默认对密钥类内容打码，从设计上避免明文暴露。

与常见的 Electron / Tauri 剪贴板管理器相比，mtuck 是原生编译的单二进制 CLI：不需要 Electron、Node 或 JVM 这类语言运行时，启动即用，不占后台 GUI 资源。它的依赖边界与可用性边界分三层说清：

- **交付形态**：MoonBit 原生编译，单二进制，无 Electron / Node / JVM 等语言运行时，不常驻 GUI；
- **依赖边界**：剪贴板读写全部在本仓库内实现（`platform/clipboard_backend.c`），不依赖任何第三方剪贴板包。macOS 与 Windows 直接调用系统原生 API，无需额外依赖；**Linux 走 `wl-paste` / `xclip` / `xsel` 这些图形服务器客户端，需用户预装其一**；
- **可用性边界**：`watch`（记录）与 `copy`（写回）需要剪贴板后端，也就是一个可连接的图形服务器（X11 `DISPLAY` 或 Wayland `WAYLAND_DISPLAY`），**纯 SSH、无图形服务器的容器里不可用**；而 `list` / `show` / `pin` / `unpin` / `rm` / `clear` / `stats` 只读写纯文本的 `history.tsv`，在任意终端环境（含 SSH、tmux、容器）都能对同一份历史做检索与管理。

### 核心功能范围
- **常驻记录**：后台按可配置间隔监听剪贴板，内容变化立即持久化；macOS 与 Windows 借助系统原生变更计数轻量判断变化，Linux 自动退化为读取比对；启动前先探测剪贴板后端是否可达，不可达时直接给出可操作的报错而不是静默失败；
- **历史模型**：最新一条始终在最前，编号即位置；重复内容自动合并并排序到最前；固定条目永不淘汰，超出容量时淘汰最旧的未固定条目；
- **内容类型判定与保密**：自动区分 URL、连接串、JWT 与密钥等类型，识别私钥块、敏感赋值、认证头、常见密钥前缀与带账号密码的连接串；密钥类内容在列表、详情和结构化输出中默认打码，显式参数才显示原文，旧数据也按最新规则重新判定；
- **命令行检索**：支持条数截断、只看固定条目、子串过滤；条目操作使用统一编号语法，支持最新一条、多选与区间批量处理；
- **脚本友好**：列表与统计支持结构化输出，便于与其他命令行工具组合；退出码区分成功、运行期错误与用法错误；
- **健壮持久化**：采用纯文本格式存储，存储层不需要数据库或第三方序列化库、可读可 diff、可手工修复；原子写入，中断不产生残缺文件；坏行跳过不影响其余数据；历史文件仅当前用户可读；
- **可测试架构**：历史模型是无 I/O 的纯逻辑，监视器把剪贴板读取抽象为可注入函数，测试不依赖真实系统剪贴板；检查、格式与测试流程接入持续集成。

### 运行环境与剪贴板后端
剪贴板属于桌面会话，因此命令按后端分成两档：

- **`watch` / `copy`（需要剪贴板后端）**：macOS 走 AppKit、Windows 走 Win32，无额外依赖；Linux 走 `wl-paste` / `xclip` / `xsel`，需预装其一，并要求一个可连接的 X11 / Wayland 会话。启动前探测图形会话、socket 与外部命令是否存在，失败即报错退出，不静默重试。
- **`list` / `show` / `pin` / `unpin` / `rm` / `clear` / `stats`（只依赖文件）**：仅读写纯文本 `history.tsv`，在纯 SSH、tmux、容器里都能用，也可被脚本直接消费。

Linux 的剪贴板读写由外部命令提供；`platform/stub.c` 只有约 30 行，仅承担 macOS / Windows 的「变更计数」快路径，缺失时自动退化为读取文本比对。

### 移植或参考说明
- 原项目名称：无（原创项目，非移植）
- 本项目许可证：Apache-2.0
- 第三方依赖：仅 `moonbitlang/x`（异步、文件系统、时间与环境等）；剪贴板读写在仓库内自实现，不引入第三方剪贴板包。
- 平台外部依赖：Linux 上需要预装 `wl-clipboard`（Wayland）或 `xclip` / `xsel`（X11）之一；macOS 与 Windows 无额外依赖。

与同类工具（Windows 剪贴板历史、macOS 上的 Paste / Maccy、Linux 上的 clipse / CopyQ 等）相比，本项目做了以下重新设计：
- 以终端 CLI 加单二进制为交付形态，不做常驻 GUI；记录与写回依赖剪贴板后端，而历史的检索与管理只依赖纯文本文件，因此可在远程终端与容器内消费同一份历史；
- 历史文件刻意选择纯文本格式而非数据库或二进制，保证可读、可 diff、可手工修复；
- 把密钥识别与默认打码作为核心默认行为而不是可选项，并在读取旧数据时按最新规则重新判定；
- 按依赖方向严格分层，纯逻辑、事件源与 I/O 相互独立，使核心逻辑可以在任意后端上快速测试。

实现分布（非空行统计，`moon check` / `moon fmt --check` / `moon test --target native` 均通过，141/141 测试通过）：MoonBit 源码约 2480 行，其中 `history` 历史模型 752 行（去重合并、固定、上限淘汰、类型判定与打码、TSV 编解码，纯逻辑无 I/O）、`watch` 轮询器 133 行、`cli` 命令层 1199 行、`platform` 后端抽象 392 行；测试约 1595 行。原生 C 共约 700 行，其中 `platform/clipboard_backend.c` 是自实现的剪贴板读写，`platform/stub.c` 仅约 30 行，承担 macOS / Windows 的变更计数快路径。由于历史模型与轮询器都不直接调用剪贴板后端（`watch` 的读取函数可注入），测试与持续集成在没有任何剪贴板后端的机器上也能全部跑通。

有效 MoonBit 代码规模目前在 2.5k 行左右，低于章程给出的 4~10k 参考区间。路线图里的图片剪贴板、按类型筛选、交互式选择界面与历史加密都会继续扩展这个规模，交付时会如实说明完成的边界。

多提交历史：仓库当前 71 个提交，全部位于默认分支 `main`，均可追溯；修复与功能改动均通过 PR 合入，并在 `docs/issue.md` 留有可复查的问题记录。
